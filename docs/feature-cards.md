# 特徴カード（ドラフト）

- 版: 0.1
- 作成日: 2026-11-22
- タグの定義: [requirements.md の 6.5](requirements.md#65-タグ)

## 書き方のルール

- 技術名、製品名、会社名は書かない。
- 1 枚に書く特徴は 1 つだけにする。
- 「〜したい」「〜がいい」のように、ユーザーの好みとして書く。❤ か ✕ かで答えやすくするためである。
- 専門用語を使う場合は、「補足」で中学生にも分かる程度に説明する。
- 「どちらが優れているか」を言い切らない。反対の好みのカードも用意する。

## 5. 1 回のセッションで出す枚数

合計は 76 枚。1 回のセッションでは、軸ごとに次の枚数をランダムに選んで、最初の山札を 19 枚作る。

| 軸 | 全体 | 1 回で出す枚数 |
|---|---|---|
| 分野 | 18 | 7（部門ごとに、関心を聞くカードを最低 1 枚入れる） |
| 言語の性質 | 20 | 7 |
| フレームワークの性質 | 10 | 3 |
| 開発環境とエコシステム | 6 | 2 |
| 部門の専用カード | 22 | 0（最初の山札には入れない） |

最初の山札を答え終えたら、関心があると判定した部門の専用カードを最大 4 枚追加する。複数の部門に関心がある場合は、関心度の高い部門から 1 枚ずつ順番に選ぶ。

並べるときは、同じ軸のカードが 3 枚以上続かないようにする。

### 5.1 経験レベルによる出し分け

経験レベルが 3 以下の人には、専門用語の多い次のカード（`advanced: true`）を出さない。外しても、言語の性質は 14 枚、フレームワークの性質は 8 枚残るので、1 回で出す枚数（7 枚と 3 枚）は満たせる。

| ID | 外す理由 |
|---|---|
| l04 | 「null」「コンパイラ」 |
| l05 | 「コンパイラ」 |
| l10 | メモリの手動管理 |
| l12 | メッセージパッシング |
| l13 | 「パターンマッチ」 |
| l14 | 式指向の書き方 |
| f09 | ビルド時のコンパイル |
| f10 | 「仮想 DOM」 |

実装は `src/lib/deck.ts`。

## 6. 確認したいこと

- **専門用語が多い（対応済み）:** 経験レベルが 3 以下の人には、専門用語の多いカードを出さないようにした（5.1）。LV.4 以上の人には、補足の説明つきでそのまま出す。
- **タグに偏りがある:** 部門については「関心を聞くカードを最低 1 枚入れる」ようにした。ただし `systems`（低レイヤ）はまだ部門になっていないため、関心を聞くカードが 1 枚も出ないことがある。
- **「パス」の意味が 2 通りある:** たとえば d08 を「パス」にしたとき、「フロントエンドが好き」なのか、単に「興味がない」なのかは区別できない。MVP ではこのままにして、結果を見て調整する。
